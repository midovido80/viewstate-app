FROZEN PRODUCT CONTEXT

Treat the following as already approved and non-negotiable unless an explicit governance conflict is found:

Product Positioning

ViewState is a generic real-estate product.

V001 first operational/deployment market:

Kuwait

Planned expansion region:

GCC

Kuwait-first is an operational decision, not a product architecture constraint.

---

Primary User

Real-estate Broker / Real-estate Consultant.

The product is primarily designed for a professional working daily with:

- Properties
- Property owners
- Buyers
- Tenants
- Buyer/Tenant Requirements
- Brokers
- Real-estate contacts

The product is mobile-first.

---

Core Operating Model

Capture → Organize → Act

Matching is the North Star outcome, but ViewState is not only a matching application.

---

Core Product Principle

Capture First → Enrich Later

The broker must be able to save useful partial information quickly and enrich it later.

Large mandatory forms must not block basic capture.

---

Basic Capture Speed Target

Basic capture of the essential information for:

- Property
- Contact
- Requirement

should target approximately:

10–15 seconds

This applies to BASIC CAPTURE only.

It does NOT mean a complete enriched record must be completed within 10–15 seconds.

---

Requirements

Buyer/Tenant Requirements are an explicit V001 core capability.

They must not be treated as an implicit sub-feature of Matching only.

---

Classification System

V001 includes an optional lightweight classification/status capability that can be associated with a Contact/Client or Property.

The approved labels are exactly:

1. Follow Up
2. Important
3. Pending
4. Order Complete / Closed Deal

This is classification only.

It is NOT:

- a task management system
- a reminder engine
- a calendar
- an automation engine
- a sales pipeline
- a transaction ledger
- a commission workflow

Do not define persistence implementation in this stage.

---

WhatsApp Communication Boundary

Both:

- WhatsApp
- WhatsApp Business

are required communication choices within the broker workflow.

At product level, the user must be able to choose between WhatsApp and WhatsApp Business when a relevant communication action is invoked, and the selected application should open.

The technical mechanism is NOT decided in this stage.

Do not choose:

- Deep Links
- Android Intents
- WhatsApp API
- WhatsApp Business API
- Share Sheet implementation
- package names
- SDKs
- libraries

Those decisions belong to a later Integration stage.

---

Kuwait Market Boundary

Kuwait is the first operational market.

The product must later support Kuwait-specific market configuration, including the ability for the broker to select Kuwait areas during property entry.

However:

- the full Kuwait area list
- grouping
- IDs
- source
- storage
- update mechanism
- database representation

are NOT part of Stage 00.2.1.

Do not design them here.
