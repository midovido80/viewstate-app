# ViewState App — UX Rules

**Status:** PRE-IMPLEMENTATION  
**Last updated:** 2026-08-13

---

## Bilingual / RTL First

ViewState is used by Arabic-speaking brokers first. English is secondary. This means:

### Layout direction
- Default layout direction: **RTL** (Arabic)
- English users switch to LTR via settings
- Use `I18nManager.isRTL` to conditionally flip flex directions — never hardcode `row` without considering RTL
- Icons that are directional (arrows, back buttons) must be flipped in RTL: use `transform: [{ scaleX: isRTL ? -1 : 1 }]`

### Typography
- Arabic body text: minimum 16pt. Arabic at small sizes is illegible on mobile.
- English body text: 14–16pt
- Headlines Arabic: 20–28pt
- Headlines English: 20–28pt
- Font family: use a font that supports Arabic script well. Recommend: **IBM Plex Arabic** or **Noto Sans Arabic** + **Inter** for English
- Never mix Arabic and Latin in the same text element if it can be avoided — use separate `Text` components

### String management
- All user-visible strings live in `src/i18n/ar.json` and `src/i18n/en.json`
- No hardcoded strings in any component. Zero exceptions.
- Keys follow `module.screen.element` pattern: e.g., `property.list.emptyTitle`
- Arabic translations are written by the Founder, not generated by AI

---

## Interaction Design

### Touch targets
- Minimum tap target: **44 × 44pt** (Apple HIG)
- Never place two tappable elements closer than 8pt apart

### Gestures
- Swipe-to-delete on list items (where applicable)
- Pull-to-refresh on all list screens
- No complex multi-finger gestures in v1

### Navigation
- Tab bar: 4–5 tabs maximum
- Deep links must work from WhatsApp share (e.g., `viewstate://property/[id]`)
- Back button always visible in stack navigators; never trap the user

### Loading states
- Every async operation shows a loading indicator
- Use skeleton shimmer (not spinner) for list/card content
- Network errors show a retry button with a human-readable Arabic/English message

### Empty states
- Every list screen has an empty state
- Empty state: icon (Ionicons/Feather) + Arabic headline + English subheadline + CTA button
- No placeholder images in empty states

---

## Accessibility

- All interactive elements have `accessibilityLabel` in both Arabic and English
- Color contrast: minimum 4.5:1 for body text, 3:1 for large text
- `accessibilityRole` set correctly on all buttons, inputs, and list items
- Test with iOS VoiceOver before every release

---

## Color Philosophy

- No pure white (#FFFFFF) backgrounds — use off-white (#F8F8F6) to feel warmer
- Primary brand color: TBD (Founder decision)
- Error: #D32F2F (red), Success: #388E3C (green), Warning: #F57C00 (amber)
- Dark mode: supported from day one via `useColorScheme`
- Never hardcode hex values in components — always reference `colors.*` tokens

---

## Forms

- All forms use `KeyboardAwareScrollViewCompat` — no exceptions
- Required fields marked with red asterisk (*) in Arabic/English label
- Inline validation (not alert dialogs) on blur
- Submit button disabled while request is in-flight
- Success feedback: brief toast (2s) in the user's language

---

## Media

- Property photos: max 10 per listing
- Photo picker uses native device gallery (expo-image-picker)
- Compression before upload: max 1200px wide, 80% JPEG quality
- Upload progress shown per image

---

## Prohibited UX Patterns (never implement these)

- Dark patterns (hidden costs, misleading copy)
- Infinite scroll without a clear end indicator
- Auto-playing video or audio
- Pop-up ads or interstitials
- Forced registration before seeing any content
