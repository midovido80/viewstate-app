## Visual Baseline — V001 (Governance Rule 14)

This is the agreed visual foundation for all V001 screens. Every screen must conform.

| Element | Rule |
|---------|------|
| Top header | **Blue** background |
| Global Search | Inside the blue top header on every primary screen (Rule 13) |
| Background | White or light (#F8F8F6) — no dark mode in V001 |
| Primary headings / key data | **Red** |
| Action buttons / Quick Add | **Blue** |
| WhatsApp actions | **Green** (#25D366 or equivalent) |
| Call actions | **Green** |
| All other colors | Minimal — do not introduce additional accent colors |

### Color tokens (locked for V001)
```
primary-blue:    #1565C0  (header, action buttons, Quick Add)
primary-red:     #C62828  (headings, key data labels)
whatsapp-green:  #25D366  (WhatsApp + Call actions)
background:      #FFFFFF  (primary)
surface:         #F8F8F6  (cards, secondary surfaces)
text-primary:    #1A1A1A
text-secondary:  #757575
border:          #E0E0E0
```

## Bilingual / RTL Rules

### Layout direction
- Default layout: **RTL (Arabic)**
- English users switch to LTR via Settings
- Use `I18nManager.isRTL` to conditionally flip flex directions — never hardcode `row`
- Directional icons (arrows, back button): use `transform: [{ scaleX: isRTL ? -1 : 1 }]`

### Typography
- Arabic body: minimum **16pt** — Arabic at small sizes is illegible
- English body: 14–16pt
- Headlines: 20–28pt in both languages
- Arabic font: must support Arabic script (IBM Plex Arabic or Noto Sans Arabic)
- English font: Inter
- Never mix Arabic and Latin in the same `<Text>` — use separate elements

### String management
- All user-visible strings live in `src/i18n/ar.json` and `src/i18n/en.json`
- No hardcoded strings in any component. Zero exceptions.
- Keys follow `module.screen.element`: e.g., `contact.list.emptyTitle`
- Arabic translations are written by the Founder, not generated by AI

## Navigation Back Behavior (Governance Rule 15)

- Navigation back must **respect device/native system behavior**
- On Android: the hardware back button and Android gesture navigation must work as expected — do not intercept or suppress them for general navigation
- On iOS: swipe-from-left edge gesture must work as expected in stack navigators
- Custom back gestures that conflict with Android system behavior are **prohibited**
- The only exception: a back action that would lose unsaved data → show the unsaved-changes confirmation (Rule 16), then respect the user's choice

## Unsaved Changes Protection (Governance Rule 16)

Every form screen that can have unsaved changes must:

1. Track whether any field has been changed from its initial value
2. When the user attempts to leave (back gesture, tab switch, hardware back):
   - If no changes: navigate away freely
   - If changes exist: show a simple confirmation:
     - Arabic: `"هل تريد الخروج بدون حفظ التغييرات؟"` / `[تجاهل]` `[استمرار في التعديل]`
     - English: `"Leave without saving changes?"` / `[Discard]` `[Keep Editing]`
3. Confirmation must be a native `Alert.alert()` — not a custom modal
4. "Discard" navigates away; "Keep Editing" returns focus to the form

## Global Search UX (Governance Rule 13)

- Search bar appears inside the **blue top header** on every primary tab screen
- Single tap activates search mode (keyboard opens)
- Results appear below the header as the user types (debounced — 300ms)
- Results grouped: Properties / Contacts
- Each result shows: type icon, primary name (Arabic preferred), secondary detail
- Tap result navigates directly to the entity's detail screen
- "No results" shows a simple Arabic/English empty state

## Interaction Standards

### Touch targets
- Minimum: **44 × 44pt** (Apple HIG)
- No two tappable elements closer than 8pt

### Loading states
- List/card content: skeleton shimmer (not spinner)
- Action buttons: spinner inside the button, disabled state
- Network errors: inline error with retry button

### Empty states
- Every list screen has an empty state
- Format: icon (Ionicons/Feather) + Arabic headline + Arabic subline + optional CTA
- No placeholder images, no emojis

### Forms
- All multi-field forms: `KeyboardAwareScrollViewCompat`
- Required fields: red asterisk (*) next to label
- Validation: on blur (not on every keystroke)
- Submit button: disabled while request in-flight

### Quick Add
- Blue Quick Add button visible on list screens (Properties, Contacts)
- Opens the "Capture First" minimal creation form
- Must be reachable in ≤ 2 taps from any primary screen

## Accessibility

- All interactive elements: `accessibilityLabel` in Arabic (primary) and English
- Minimum contrast: 4.5:1 for body, 3:1 for large text
- `accessibilityRole` correct on all buttons, inputs, list items

---

## Prohibited UX Patterns

- Dark patterns of any kind
- Forced registration before seeing any content
- Pop-up ads or interstitials
- Auto-playing audio or video
- Infinite scroll without a clear end state
- Custom back gestures that override Android system behavior (Rule 15)
- Hardcoded strings in any language (must use i18n keys)
- Additional accent colors beyond the V001 visual baseline (Rule 14)
