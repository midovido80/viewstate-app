---
name: Wanted catalog selection
description: Product boundary between the Person-led Wanted catalog and Requirement specifications.
---

From Person Details, Seeker Add Requirement starts with Wanted already known. The user chooses Rent or Buy, Property type, and (for Apartment) Studio or Standard once, then enters specifications directly. A generic Requirement editor must not repeat those selection screens; Back should let the user revise a catalog choice without needlessly losing later values.

**Why:** The founder's Arabic recording showed the same Rent/type/subtype decisions repeated in the Requirement form after catalog selection, making the save journey confusing.

**How to apply:** Treat catalog selections as route context for new Wanted Requirements and as persisted context for edits. Studio remains a dedicated Wanted form, Standard a generic Requirement form. Keep Offered capture separate.
