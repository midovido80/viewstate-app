---
name: Visible interaction affordances
description: The approved ViewState rule for presenting entities, resources, and actions consistently.
---

Any entity or resource with a meaningful destination or action must be presented as an obviously interactive control everywhere it appears. Use a button, card, bordered action row, chevron/action icon, and a clear pressed state as appropriate; never hide navigation behind ordinary-looking text.

Pure informational values such as price, area, floor number, description, or a standalone percentage do not need to be interactive.

**Why:** Users should be able to predict which properties, people, requirements, matches, attachments, maps links, phone numbers, and messaging actions can be opened or acted on.

**How to apply:** Apply the rule whenever a future gate touches an entity/resource presentation. Keep each gate scoped; a complete app-wide audit belongs to its separately approved gate.
