# Approved message import — 2026-11-07

Scope approved by the founder: selected Android shares and pasted text; editable
suggestions; review before original property/request forms; private originals;
offline use; duplicate warning; split independent text listings; attach incoming
media to an existing intake draft. Business Platform bot/history export remains
outside this package. Existing property schemas, validators and matching remain.

## Implemented journey

- Home/Quick Add Import opens `/intake`. Phone contacts retain an explicit separate
  action on that screen. No contact scanning occurs for message import.
- Paste text or pick media. Explicit shares become account-scoped inbox entries;
  the arrival banner does not replace the current form or navigate over it.
- Local Arabic/English rules suggest intent, transaction, catalog type, Kuwait
  area(s), explicit counts, size/block, KWD amount/budget range, rent cadence and
  recognized services. Unknown/ambiguous/foreign-currency values need review.
  This is deterministic extraction, not a cloud AI or a promise to understand all
  dialects, wording or listings. The source text remains available alongside it.
- Explicitly confirm source/person, transaction, type, rent cadence and review.
  A sender is never assumed to be an owner. Unknown source can be completed later.
- Offered records use the existing CaptureContext and capture routes. Existing
  nonblank capture is never replaced. Studio and client requests use independent
  original-form sessions keyed by import ID. Required form rules still apply.
- Requests require a real Seeker person and remain outside offered Properties.
  Raw request messages/media stay in the private inbox, not shareable notes.
- Imported offered media is copied for form ownership; removing a form attachment
  does not delete its retained inbox original. Attachments can be opened for review.
- Save in the original form is the business-record commit. Its existing Match now
  scope remains unchanged. An intake receipt says the form was prepared, not that
  a property/request was saved. Saved receipts reopen their saved record.
- Explicit duplicate warnings cover normalized messages and similar existing
  type/area/price records. They never silently merge people or listings.
- Explicit separator/blank-line splitting is proposed only when every part looks
  like its own listing. Media-bearing messages stay together for manual review.
  Media-only receipts can attach their files to another untransferred inbox draft.
- Local composition/review autosave and background flush supplement the existing
  Back/Continue draft handling. Unconfirmed writes retain inputs and allow retry.
  Inbox mutation is serialized and takes the scoped cross-window lock when present;
  stale reviews cannot replace a claimed/completed handoff.

## Native and privacy boundaries

The native module and its offline models are documented in
`artifacts/mobile/modules/viewstate-import/README.md`. No WhatsApp account, token,
Business Platform webhook, paid AI service, server permission or Supabase schema
was configured. No full conversation is read. Source text is a never-share private
property note; original forms, permissions, media access and sync of saved records
remain authoritative. Intake drafts are device/account-local, not cloud snapshots.

Existing SDK 54 is retained. Babel now resolves the preset through the installed
Expo package for pnpm workspace reliability, without changing the lockfile or SDK.
Generated root native projects remain ignored, while local module native source
is now tracked. No app identity, signing key, Google callback or EAS project change.
